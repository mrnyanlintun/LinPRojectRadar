# PART A — THE AUTHORING CONTRACT

## A0. The five things that decide everything else

1. **A document reaches a module through three separate paths**, and an author must know which one
   a field is on:
   - **Scalar path** — a named extraction key maps to a named `signalInputs` field
     (`extraction_merge._NUMERIC_EMISSIONS` / `_DATESTR_EMISSIONS`). Fixed, hand-written table.
   - **Structure path** — a `*_json` table or a group of scalars is assembled into a *governed
     structure* (`documents._baseline_structures`, `_run69_structures`, `_run80_a3_structures`).
     Most modules that band read a structure, not a scalar.
   - **Recognition path (Run 111)** — a model is shown the labels a document printed and asked
     which one answers a specification. **Requires a model key. There is none here.** Four modules
     (A4.5, A4.6, A4.8, A4.9) are on this path only.
2. **Structures are all-or-nothing.** If one required field of a structure is missing, the key is
   not written at all and the module abstains. Half a table is worth nothing.
3. **An abstaining module is not a zero.** It is removed from the category average. A category
   with no banded module carries no posture, and then **no status is published at all**.
4. **All five of A1, A2, A3, A4, A6 must carry a posture** or the project publishes
   `Awaiting analysis`.
5. **`Complete` overrides everything, including that gate** — see A6.

## A1. The twenty-seven document types, field by field

`extraction_fields.DOC_TYPES` holds **exactly 27** entries; `ALL_FIELDS` holds **112**.
Both premises in the briefing check out. `UI_ONLY_DOC_TYPES` holds **15 more** (see A1.29),
`LEGACY_TYPE_ALIASES` holds **1** (`submittal` → `submittal_register`), plus the `UNMAPPED`
sentinel. Across the 27 types the extractor asks for **254 (type, field) pairs**.

**Column key used in every table below:**
- **→ si** = the `signalInputs` field the value lands in (scalar path).
- **→ struct** = the governed structure it helps build.
- **Verdict** = the measured end-to-end result on the 21-document census fixture:
  - `MOVES` — removing this value changed at least one module's **band**.
  - `SI` — it changed the assembled signal inputs but **no band moved on this corpus**.
  - `INERT` — removing it changed **nothing at all** downstream.
  - `RECOG` — it reaches the evidence store and is only readable by the recognition step (needs a key).
  - `(n/t)` — not present in the census fixture, so not measured; the path is stated from code.

  **Read `INERT` carefully.** It means *inert on that corpus*. Several `INERT` fields are inert
  only because a **higher-precedence document supplied the same figure** (see A4). It is still a
  correct instruction to the author: *do not expect this value to change a reading*.

## A2. File format — which structures are parsed from bytes

`documents.py:791` is right that a risk register in a PDF yields no rows. Measured across the tree,
**exactly two readers open the document's own bytes, and both are DOCX-only** (`docx_text.is_docx`,
which sniffs the ZIP magic before trusting the MIME type):

| structure | byte reader | extraction fallback? |
|---|---|---|
| **Risk register rows** (`ProjectRisk`, `registerExposure`, `costRiskModel`) | `risk_register.risk_rows_from_document` | **NO. None. Deliberate.** A register in a PDF yields no rows and says so. |
| **Schedule activity table** (`ScheduleActivity` → `milestoneHistory` → `milestoneForecastHistory`) | `schedule_table.activity_rows_from_document` | **YES** — falls back to `milestones_json` from the extraction. |

**Every other table is extraction-returned**, i.e. it arrives as a `*_json` field the model filled
in, and the file format does not matter: `schedule_network_json`, `schedule_calendar_json`,
`lookahead_activities_json`, `resource_profile_json`, `baseline_curve_json`, `modifications_json`,
`quality_requirements_json`, `critical_quality_failures_json`, `environmental_requirements_json`,
`environmental_corrective_actions_json`, `submittal_decisions_json` (+ the two rejection tables),
`reference_class_json`, `open_critical_ncr_json` and the other NCR override tables.

**So the answer to the order's question is: `risk_register` is the ONLY document type with the
constraint. Author the risk register as DOCX with a real table, or A3.6 can never band from a
document.** (A schedule in DOCX is also read directly, which is *better* than the JSON fallback
because the whole table survives without competing for the model's output budget.)

**Which `*_json` fields have declared table shapes** — 13 of the 27 types carry at least one:
`monthly_report`, `schedule_update`, `change_order`, `inspection_report`, `ncr_log`,
`subcontractor_report`, `lookahead_schedule`, `resource_report`, `quality_audit_report`,
`environmental_report`, `historical_data`, `time_phased_schedule`, `submittal_register`.
**The other 14 types can carry no table at all**, which is why A4.5 and A4.9 cannot be served
(A5).

## A3. The tables — exact column headings a parser recognises

Every reader normalises a heading by lower-casing and collapsing separators, so

## A6. Authoring for a target status

### A6.1 The arithmetic, verbatim from the executing code

**Category** (`category_posture.py`): A1–A4 **average** their banded modules' scores; A6 takes the
**worst**. Score: Green **+2**, Yellow **+1**, Amber **−1**, Red **−2**. Bands: ≥1.5 Green,
≥0.5 Yellow, ≥−0.5 Amber, below −0.5 Red. **Every boundary inclusive on its lower side.**
An unbanded module is not in the average and is **never** a zero.

**Project** (`project_posture.py`): weighted sum of the five category scores, weights
**A1 0.28 · A2 0.28 · A3 0.17 · A4 0.11 · A6 0.16**, banded on the same cuts. **No override.**
A missing category is dropped from the denominator and the rest renormalised — but the
**required-core gate** (`compute._REQUIRED_CATEGORIES = ("A1","A2","A3","A4","A6")`) means a
missing category publishes `Awaiting analysis` before renormalisation ever matters.

### A6.2 Target: **Green** — weighted sum ≥ 1.5

With all five categories carrying a posture, the sum is
`0.28·A1 + 0.28·A2 + 0.17·A3 + 0.11·A4 + 0.16·A6`.

- **All five Green** → 2.00. Comfortable.
- **Four Green + A6 Amber** → 1.52 → **Green**, by 0.02. This is exactly what the 21-document
  census fixture produced (measured: `A1 Green +2; A2 Green +2; A3 Green +2; A4 Green +2;
  A6 Amber −1 — weighted sum 1.52 → Green`).
- **Four Green + A4 Yellow** → 1.89 → Green. A4 is only 0.11; it is very hard to move the project
  from A4 alone.
- **Four Green + A2 Yellow** → 1.72 → Green. **A1 or A2 Yellow alone still leaves Green.**
- **A1 Yellow AND A2 Yellow** → 1.44 → **Yellow**. Two heavyweights are what tips it.
- **Any one of A1/A2 Amber** with the rest Green → 1.16 → Yellow.

**Recipe for Green:** author cost and schedule cleanly — CPI ≥ 1.00 and every A1/A2 module Green —
and you may leave one non-core category adverse.

### A6.3 Target: **Yellow** — 0.5 ≤ sum < 1.5

- A1 Yellow, rest Green, A6 Amber → 1.24 → **Yellow** (this is exactly the ten-period Run-107
  fixture, measured).
- A1 Yellow + A2 Yellow + A3/A4 Green + A6 Green → 1.44 → Yellow.
- A1 Amber + rest Green → 1.16 → Yellow.

**Recipe for Yellow:** put **one** heavyweight (A1 or A2) at Yellow or Amber and hold the rest.

### A6.4 Target: **Amber** — −0.5 ≤ sum < 0.5

- A1 Amber + A2 Amber + A3 Yellow + A4 Yellow + A6 Green → 0.04 → **Amber**.
- A1 Amber + A2 Amber + A3 Amber + A4 Amber + A6 Green → −0.52 → **Red**, just.
- A1 Red + A2 Yellow + A3 Yellow + A4 Yellow + A6 Yellow → 0.16 → **Amber**.

**Recipe for Amber:** both heavyweights Amber, the small categories at Yellow, A6 no worse than
Green. It is a narrow band — check the arithmetic on the exact combination you author.

### A6.5 Target: **Red** — sum < −0.5

- All five Amber → −1.00. All five Red → −2.00.
- A1 Red + A2 Red + rest Amber → −1.56.
- A1 Red + A2 Amber + A3 Amber + A4 Amber + A6 Amber → −0.84.

**Recipe for Red:** A1 and A2 both Red is sufficient on its own (−1.12 with the rest Green would
be… actually 0.28·−2 + 0.28·−2 + 0.17·2 + 0.11·2 + 0.16·2 = −0.24 → **Amber**). **Red requires
adverse readings across at least four of the five categories.** The weights make an isolated
catastrophe impossible to publish as Red; that is the deliberate consequence of removing
worst-wins.

### A6.7 Target: **Complete** — a delivery state, not a posture

`compute.delivery_complete(signal_inputs)`, read verbatim, requires **all** of:
1. `bac` is a number **and `bac > 0`**;
2. `ev` is a number **and exactly equal to `bac`**;
3. `pv` is a number **and exactly equal to `bac`**;
4. `ac` is a number **and exactly equal to `bac`**;
5. `actualPctComplete` (falling back to `pctComplete`) **== 100.0**.

Any missing figure is False. **Equality is exact — no tolerance.**

**Measured:** with `bac = ev = pv = ac = 4,000,000` and `actualPctComplete = 100`, the published
status is **`Complete`** while the underlying `fused_band` was `Yellow`. Setting
`actualPctComplete = 99` → `Yellow`. Setting `ac` 2% over BAC → `Yellow`.

**Complete is applied AHEAD of the required-core gate** (`_published = _COMPLETE if _complete else
(_AWAITING if …)`). **A project can publish Complete with categories unassessed.**

**What the other modules do on a completed project** (measured):
- **A1.7 TCPI ABSTAINS** — `BAC − AC = 0`, so there is no remaining budget to measure against.
  It refuses rather than returning Red. Expect A1 to lose a module.
- **A1.9 Budget Execution goes RED** — cumulative spend equals the full budget while the
  expenditure baseline at that period is lower.
- A1.6 Green, A1.8 Green, A1.2 green, A1.5 Green; A2, A3, A4, A6 unchanged; the category postures
  and `fused_band` are still computed and still stored beside the published word.

**To author a Complete project:** state `bac`, and state EV, PV and AC as **the identical number**,
and state percent complete as exactly 100. The cleanest single document is a `monthly_report`
(`budget_at_completion`, `earned_value`, `planned_value`, `actual_cost`, `actual_percent_complete`).
Beware the precedence table: a `pay_application` will **outrank** the monthly report for `ac` and
`actualPctComplete`, and a `schedule_of_values` will outrank it for `ev`. **If you author a
Complete project, do not also author documents that state a different EV/AC/percent.**

## A8. The traps — where authoring one figure moves another module

Found by measuring shared inputs, not by recall.

1. **Run 86's trap, confirmed in code.** `spi = ev / pv`, and **when `pv` is absent it falls back to
   `actualPctComplete / plannedPctComplete`**. So a planned percent above the actual percent
   drives SPI below 1 and tips A1.2 and B1.1. **Never state `planned_percent_complete` above
   `actual_percent_complete` unless you intend a schedule problem.**
2. **`items_inspected` is two denominators.** A6.1's first-pass ratio *and* A4.4's NCR rate.
   Raising it improves A4.4 and worsens A6.1 unless `items_passing_first_inspection` rises with it.
3. **A change order re-bases the whole project.** `revised_contract_sum` is **tier 0** for `bac`
   and `revised_completion_date` is tier 0 for `baselineEnd`. One change order silently overrides
   the contract, and every EVM ratio moves.
4. **An RFA log becomes a submittal register.** `rfa_total`/`rfa_rejected` write
   `submittalsTotal`/`submittalsRejected` at tier 1.
5. **The cost report outranks the pay application on contingency.** State the pair in both and the
   cost report's figures are what A3.2 reads.
6. **`bac` is also A3.6's base cost.** Changing the budget changes the P80 cost-risk spread.
7. **One overdue RFI reds A4.2** (measured: 0 → Green, 1 → Red, out of 40).
8. **A single `Marginal` contractor rating ambers all of A6**, which costs the project 0.32 on the
   weighted sum (from +0.32 to −0.16) — enough to move Green to Yellow on its own if A1 or A2 is
   not clean.
9. **A structure missing one provenance field silently costs a module.** Measured: removing
   `schedule_version` from a schedule update destroys `scheduleNetwork` and un-bands A2.1;
   removing `resource_plan_version` destroys `resourceProfile` and un-bands A2.9;
   removing `lookahead_status_date` un-bands A2.8; removing `quantity_source` un-bands A3.3.
   **The provenance fields are not decoration.**
10. **`evidenceQualification` is a live gate.** Measured: removing it from the signal inputs
    un-banded A6.1, A6.2, A6.3, A6.4, B1.1 and B1.2 and took the project to `Awaiting analysis`.
    It is assembled automatically on the document path — but only on the document path.
11. **`document_risk_score` outside 0.0–1.0 refuses the ENTIRE document**, not just that field
    (`emit_observations` validates before it emits anything). Same for any malformed numeric.
12. **The 8-period cliff.** A1.5 and B1.1 appear at period 8 and both can be adverse. A project
    authored to be Green over 7 periods can flip at period 8.
