# Run 20 cycle 10: the names that claimed a method the code does not perform

Run 19 recorded twenty-three registered modules whose NAME asserts an analytical method the
code does not perform, and eight more whose name or reported claim rests on a canonical data
structure this repository does not hold. A name is a scientific claim. Discrete Event Simulation
asserts an event schedule, entities, resources and a clock. Schedule Risk Analysis at the
eightieth percentile asserts a network sampled to a distribution. Rough Sets asserts an
information table of objects and attributes. None of those structures is in the corpus.

## The canonical route was tested first, and it fails on evidence rather than on effort

For every one of the thirty-one the canonical route was examined before the naming route. The
question asked of each was the one the cycle instruction sets: is the structure available from
actual controlled project evidence, can it be represented without fabricating data, does the
controlling specification establish it, and would implementing it produce a real method rather
than empty scaffolding.

The answer is the same in every case, and it is recorded mechanically rather than asserted. The
production input contract the caller assembles carries no schedule network, no risk register
with cost impact distributions, no event schedule, no stocks and flows, no information table of
objects and attributes, no alternative set, no agents, no external price index with a publisher
and a vintage, no time-phased planned value curve, no independent estimate prepared by another
party, and no per-field source records. None of those is a declared canonical structure key
either, so none is reachable through the layer that already gates the six modules which DO have
their structure and which abstain when it is absent. Run 20 is forbidden to invent any of them,
and inventing one would have been the worse outcome: empty academic scaffolding is not a
successful implementation.

The six modules that genuinely carry a canonical structure keep it and were given no naming
override, which is checked, because a truthful label must never become a way of avoiding an
implementation that is actually possible.

## The resolution, and the one thing it deliberately does not do

Each of the thirty-one now carries, on the record the interface and the export publish, the
truthful name of the computation it performs, the canonical structure that is absent stated in
plain words, and a disposition. Twenty-four are CORRECT_PROXY_ONLY. Five are FUTURE_RESEARCH_ONLY
and remain disabled. Two are OWNER_DECISION_REQUIRED. One is REGULATORY_VERSION_BLOCKED and one
is EMPIRICAL_VALIDATION_BLOCKED, and those last two are not naming faults at all: those modules
are named for what they do, and what is missing is evidence behind a claim.

THE PARTICIPANT SURFACE IS NOT RENAMED, and that is a determination rather than an omission. The
served participant package is frozen and checksummed, the study is mid-sequence, and the name a
participant reads is part of the instrument. Renaming it is an owner decision about the
experiment, not a remediation, and this run has no authority to make it. The truthful name
therefore reaches the interface response, the export and the methods documentation only, by
exactly the mechanism Run 1 used for the thirty proxy qualifiers, and the suite proves that no
truthful name appears in any of the three keys the participant ledger renders.

NOTHING WAS ACTIVATED BY BEING RENAMED. A truthful name is not a rehabilitation. The five
disabled modules with false names stay disabled, voting stays at exactly two, and Material Cost
Variance was deliberately given no label because its disposition is an evidence question and not
a naming one.

## Guard non-vacuity

Five deliberate violations were introduced and each guard was required to fire by name, then the
state restored and the guard required to go green again. A registry rename that leaves a stale
claim standing is caught. A truthful name that merely repeats the registered claim, casing and
spacing aside, is refused at construction. A disposition outside the permitted vocabulary is
refused at construction. A label deliberately removed from the table is caught by the coverage
check. A truthful name deliberately written into a participant ledger key is caught by the leak
check. The attachment itself was shown to be capable of not firing, so the check that an
unlabelled module is left untouched is not vacuous.

The existing Run-20 production manifest guard fired correctly and by name before anything was
transcribed: it named the changed registry file and the new production file, both undeclared at
that moment, and the cycle-count check refused the manifest until the new cycle declared itself.
