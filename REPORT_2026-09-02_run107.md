**What is missing, module by module, and it is stated on the reading rather than filled in.** Each
arm that cannot be formed returns Not Assessed and says what it needed:

- **A1.6 time-variance arm** needs the approved calendar's **working days per period** and the
  **remaining planned working duration** on the time-phased baseline. SV(t) = ES − AT comes off the
  planned-value curve in *periods*; the owner's ladder divides it in *working days*. No calendar
  reaches this module, so a period is never assumed to be any number of working days.
- **A1.6 hard override** needs `approved_milestones` with a planned and a required period index.
  With none declared the override is reported **NOT EVALUABLE**, not "did not fire".
- **A1.9 period arm** needs `period_actual_cost`. The cumulative actual is never divided by the
  period plan.
- **A1.9 funding override** needs `approved_cumulative_funding_limit` (or a cash-flow limit).
- **A1.11** needs **BAC**; without it *both* components are Not Assessed and no colour is asserted.
  Its override additionally needs `remainingContingency`; an unreported contingency is never
  treated as sufficient.
- **A4.5 allowance arm** needs `weather_allowance_days` **and** `weather_days_approved`. Days
  *claimed* are never substituted for days *approved*.
- **A4.5 float arm** needs stated remaining total float on the affected path (see §4).
- **A4.7** needs each process stage placed in one of the owner's four escalation classes **by the
  process record**. With none declared the reading is Not Assessed — never Green.
- **A4.8** needs a mappable rating for **every** firm; one narrative-only record makes the whole
  module Not Assessed, which is the owner's own eligibility rule.
- **A4.9** needs `day_basis = approved_calendar_working_days`. A register counting *calendar* days
  is Not Assessed rather than converted: no calendar reaches the module. Its Yellow/Amber split
  needs the item's own `criticality` (see §4).

**A1.5 could not band on the corpus and this is a real supply finding.** It is defined on a cost
performance history of at least eight readings, and this platform assembles that history *only*
from the project's own earlier periods (`documents._period_history`). There is no field, no
structure and no route by which one may be typed in, and none was invented. The Run 107 fixture
therefore builds **nine earlier periods** through the real upload and compute routes so the
history exists as the platform assembles it.

## 3. The PM review state — proved on the page the owner loads

**How it is kept out of the six project statuses, structurally rather than by promise.**
`pending_pm_review` is never written to `status_color`, never to `project_status`, never to a
category's `status`. A held module returns `status_color = None`, which is this platform's
existing, proven meaning of "asserts no band": `category_posture` averages only banded modules, so
a held row contributes nothing, cannot drag its category down and cannot lift it. The held state
lives in its own key, `module_state`. The rendered page was searched for the string
`pending_pm_review` and **it appears nowhere**.

**Why it is not `EXCLUDED_FROM_CATEGORY_ROLLUP`.** That set (`{B1.2}`) is a *permanent* property —
B1.2 is derived from the rollup it would feed, so it may never enter it on any project in any
period. The hold is a *per-reading* state: the same module enters the rollup the moment a
disposition is recorded, and enters it on a Green reading with no review at all. Putting A4.8 in
that set would hold it out of Document Signals forever, the opposite of the owner's ruling. The two
were established as different mechanisms and were not conflated.

**How a disposition is recorded.** Two new routes, `projectmodulereview` (write) and
`projectmodulereviews` (read-back), both on the existing `/exec` surface with the existing
membership check. The five dispositions are imported from
`research_decision.PROJECT_DECISION_DISPOSITIONS` — **the same five the Governance Decision card
offers**, including "Override finding" → `reject`. `simulation.pm_review.DISPOSITION_EFFECT` is
keyed on exactly those codes and the driver asserts set equality and label equality, so a second
vocabulary cannot grow. Rationale is **required** for Modify and Override (refused without one, and
that refusal is exercised). A disposition outside the five is refused. The platform's own mapped
posture, the source rating and the document identity and version are read **from the stored row**,
never accepted from the client. The recorded review reaches the module through
`documents.run_and_store`, which merges the latest review per module, period-scoped, onto
`si["moduleReviews"]`; the key is absent where nothing was recorded.

**What the audit record holds** — every field the order enumerates was read back out of the
append-only table and asserted present:

`source_rating` (`Marginal`) · `source_document_id` (`Subcontractor Performance Report SPR-2026-03`)
· `source_document_version` (`Rev 1`) · `assessment_period` · `normalisation_rule` ("the owner's
Run 107 label ladder") · `normalisation_rule_version` (`run107.subcontractor_reported_rating.v1`) ·
`platform_mapped_posture` (`Amber`) · `pm_participant_id` · `pm_recorded_at` · `disposition` ·
`disposition_label` · `rationale` · `evidence_references` · `pm_final_posture` (`Yellow`).

**Proved on the rendered page, in Chromium, twice, with nothing under test supplied to a renderer.**
No brief is composed, injected or handed to a render function; `window.LinResults.rowFor` is only
*read*, to wait for the row the page fetched. `drive_run96_card.py` and `drive_run94_charts.py`
were not used.

## 4. Does Critical Path Analysis's float and criticality reach A4.5 and A4.9? **No.**

Established by reading `registry.run_all`, not assumed. Pass 1 dispatches every flat-input module
with `run_module(new_id, si, rand, period_cutoff)` — `si` and nothing else. The **only**
cross-module channel is the nested-input adapter's `signal_array`, built from
`signal_package.array_entry`, whose keys are exactly `{module_id, method_class, status_color}` —
**no figures at all**. A4.5, A4.7, A4.8, A4.9 and A2.12 are all flat-input modules and none is in
`NESTED_INPUT_MODULES`, so the adapter never runs for them either.

A2.12 *does* compute what the order describes — verified on the corpus project:
`controlling_path_total_float_days = 25.0`, `near_critical_count = 0`,
`near_critical_activities`, `near_critical_band_days`, `minimum_total_float_days`. **The path does
not exist**, so:

- **A4.5's float arm** bands on the float the **weather record itself** states for the affected
  path, and the boundary text on the reading says so in as many words: "it is NOT read from
  Critical Path Analysis, which no path connects to this module". Where the record states no float
  above zero, the arm is Not Assessed and the allowance arm bands alone. No float figure is inferred.
- **A4.9's criticality** is read from the **register's own `criticality` field**, which already
  existed on the structure. Where an item does not state it and is 1–5 days late, that item cannot
  be banded (Yellow cannot be told from Amber) and is absent from the aggregation rather than
  counted as favourable. Criticality is never guessed.

Building the connection would have meant inventing a join between two structures the platform keeps
separate. It was not built.

## 6. The provenance fix, and what could not be recorded

**A1.7 TCPI and A1.8 VAC — fixed.** Both returned a bare dict carrying a `status_color` and never
went through `models.banded`, the function that makes a band and its provenance impossible to store
apart. Both now return through it. **No boundary moves, no citation is rewritten, and the rendered
sentence is byte-identical** (`TCPI: 1, the cost efficiency…`). The citation is read from
`registry.BAND_SOURCES` — still the single source of truth — rather than copied.

The two provenance classes are **not** the same and both are written, using the split
`models.banded` provides for exactly this case:

- `band_basis_provenance_class = CODIFIED` — the measure and its anchor are fixed by a standards
  body. PMI defines TCPI as the efficiency the remaining work must achieve and VAC as budget less
  forecast; **1.00** and **0 per cent** are definitional boundaries stated by the source.
- `band_boundary_provenance_class = CONVENTION` — the second boundary of each (1.10, and the
  −11.11 per cent restating a cost index of 0.90) rests on Christensen and Heise's empirical 0.10
  stability finding *applied by inference*. A journal study is a published basis, so it is not
  OWNER-CALIBRATED; it is not a standards clause fixing a band edge, so it is not CODIFIED.
- `threshold_source = formal_external_basis` for both. **`THRESHOLD_SOURCES` was not widened** —
  this is one of the three values it already held.

**This classification is a judgement and is flagged as one**, in the code and here, for the owner's
ruling. It is recorded rather than left blank because the order says to record what can be recorded.

**The concealment is removed.** `decision_brief._boundary_and_basis` fell back to
`registry.BAND_SOURCES` and **stamped "CODIFIED"** onto any row that stored nothing. That fallback
is deleted. A row with no stored basis now prints none, which is the true statement about it — the
driver asserts exactly that. Stated plainly: a **pre-Run-107** A1.7 or A1.8 row recorded no basis,
and the card will now say so rather than printing a citation the row never held. No stored row is
rewritten.

**`research_export._RUN4_BAND_SOURCES` was examined and deliberately left alone.** It is an
explicit "mirror, do not import" copy in a committee-facing export, and it prints the **citation** —
it never asserts a provenance class, so it conceals nothing. It is a frozen research artefact and
was not touched.

**A1.2 CUSUM's `maxStat >= 0.6 * H`.** Reported, not invented. What it does:
`models_sim.cusum_status` returns `red` on a breach of the decision interval H, `amber` when the
maximum CUSUM statistic has reached **60 per cent of H**, else `green`. H itself is derived from
`h_units = 5` sigma in `cusum_series`, which is a conventional tabular-CUSUM design constant. **The
0.6 has no basis anywhere in the tree** — it appears once, in that one comparison, with no comment,
no citation, no `band_reference_data.json` entry and no `BAND_SOURCES` entry. A basis for it would
need to state a *quantity* (the fraction of the decision interval consumed), a *direction*
(adverse upward), and either an ARL-based derivation from the chosen k and h — i.e. the average run
length at which a warning limit is set on a CUSUM chart, which is what a statistical quality-control
source would supply — or an explicit owner tolerance stating why 60 per cent of the decision
interval is the point at which a cost-performance drift becomes a finding. **Neither exists and
neither was invented.** A1.2 abstains on the corpus (it needs two periods of SPI history) so it
does not currently set a posture there.

**A3.2 and A3.3 — the order's premise is wrong and this is the finding.** They do **not** band "on
CONVENTION with no cited document". Both cite `RESEARCH_1_threshold_bands_eight_metrics.md`, by
section number and with the quoted words (section 30 for A3.2's burn heuristic, section 44 for
A3.3's "conventional practitioner values, not codified"). What is actually wrong is worse and is
now recorded in §10: **that document does not exist in this repository.** There is no `research/`
directory and no file of that name anywhere in the tree.

**What was recorded.** Four bands that carried a provenance class but no addressable identifier now
carry one, so an owner can name the tolerance he wants moved:

| module | new `band_basis_id` |
|---|---|
| A2.8 Look-Ahead Schedule Health | `owner_configured_lookahead_readiness_tolerance` |
| A2.9 Resource Loading Index | `owner_configured_resource_peak_load_tolerance` |
| A3.2 Contingency Burn Rate | `owner_configured_contingency_burn_tolerance` |
| A3.3 Labor Productivity Index | `owner_configured_labor_productivity_tolerance` |

**What could not be recorded:** a basis for A1.2's 0.6; and a resolvable citation for A3.2 and A3.3,
