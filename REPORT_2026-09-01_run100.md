## Bug one — A6 refuses evidence it was given

### The conflict, named exactly (§2.1)

- **Field:** `docRiskScore`
- **The two figures:** `0.15` and `0.10`
- **The documents:** `submittal_register` (0.15) against `inspection_report`, `field_report` and
  `oac_minutes` (0.10). Four documents, two distinct values.
- **Writer tier:** `0` for all four. **`as_of`:** `2026-03-31` for all four.
- **The rule that declared it:** `server/app/documents.py:2060-2081`, in the Category-9 evidence
  record builder — *two documents of equal declared writer precedence, dated the same, stating
  different values for one field, so the declared precedence rule cannot decide between them.*
- **The record** carries `"material_conflicts": conflicts` and is applied **flat** to every module
  that asks (`qualification_boundary.declared_evidence:172`, where `per_module` falls back to the
  whole record). One conflict in one field therefore refused all four A6 modules.

### Is the disagreement real? No.

**It is spurious, and it is the wrong-field shape §2.3 describes.** `document_risk_score` is
defined per document, not per project. The extraction prompt says so in as many words —
*"document_risk_score, if requested, is a number between 0 and 1 inclusive, where 0 is no concern
and 1 is severe concern"* (`extraction_client.py:393`) — and it is requested separately from each
of the **seven** doc types in `extraction_merge.DOC_RISK_DOC_TYPES`. The A4.1 note at the
derivation site says it outright: what the pipeline supplies is *"a single number per document"*
(`documents.py:2281`).

A submittal register scoring itself 0.15 and an inspection report scoring itself 0.10 are each
describing **themselves**. They are not two answers to one question, so there is nothing for the
precedence rule to fail to decide. "The documents disagree" is a category error here, not a
finding.

Checked and ruled out before concluding that:

- **Not a unit or format artefact.** `_v(o)` does not normalise, but `0.15` and `0.10` are
  genuinely different numbers, not `95` vs `95.0` vs `95%`.
- **Not a stale value beating a current one.** All four carry the same `as_of`.
- **Not a precedence bug in `_first_or_none`'s shape.** Run 81's defect was the wrong *instance*
  being picked. This is the wrong *comparison* being made at all.

### What changed

`documents.py`, one exclusion with the reason written at the site: `docRiskScore` is not compared
across documents, because it is not a shared assertion about the project.

**This is not suppression (§11.1), and it is provable.** The check is still live for every other
field, and a zero is still a value:

```
genuine bac disagreement (4,000,000 vs 5,000,000) -> CONFLICT RECORDED
ev 0 against ev 100                                -> CONFLICT RECORDED
two documents self-scoring 0.15 and 0.10           -> []
```

`docDate` would have had the identical shape, but it is in
`field_registry.UNEMITTABLE_FIELDS` and never becomes an observation. **`docRiskScore` is the only
per-document self-descriptive field in the emittable vocabulary**, so this is one field, not a
class of disagreement.

### Measured, on the real route

21 documents seeded through the real upload route, computed through the real compute route,
`projectcategoryapply` pressed. Nothing under test supplied.

| | before (`04d4691`) | after |
|---|---|---|
| `material_conflicts` | 1 (`docRiskScore`) | `[]` |
| A6 modules computing | **none** | **A6.1, A6.2, A6.3** |
| A6 abstentions | 4, all *"1 unresolved material consistency conflict"* | 1 (A6.4) |
| modules computing overall | 9 | 12 |

**A6.4 still abstains, for an honest and different reason:** *"Awaiting a governed contractor
assessment record."* It reads exactly one input, `contractorAssessmentRecord`, and no document
type in the corpus produces one. That is a missing document type, not a refused one.

### One fixture field for §2.2's recipe

`environmental_report.compliance_rate` is validated as a **0–1 fraction**; a value of `100` is
rejected outright and the whole document is discarded. Run 99's fixture carried `100`, so the
environmental report never landed and A6.3 could not compute even after the gate cleared. With
`1.0` it computes. **A generating model must emit this field as a fraction, not a percentage.**
This is the only field of that shape I hit.

Iterations: **two**. (1) exclude `docRiskScore` → conflict cleared, A6.1 and A6.2 computed, A6.3
still dark. (2) hypothesis: the environmental document was rejected at extraction, not gated —
confirmed in the log, corrected the fixture value to `1.0` → A6.3 computes. Goal met.

## Bug three — the recorded applier ignored the project's figures

### What it was

`RecordedSpecApplier.apply` tried the prompt sha256, then fell back to the **bare category key**:

```python
if key in self._recorded:            return self._recorded[key]
if category_key in self._recorded:   return self._recorded[category_key]   # the defect
```

The only question the fallback asked was *"is this category A1"*.

### Measured, before and after, two projects through the real routes

| | project X (100%, EV=AC=BAC=4,000,000) | project Y (25%, EV 1,000,000, AC 1,050,000) |
|---|---|---|
| **at `04d4691`** | `computed`, **`Green`** | `computed`, **`Green`** |
| **after** | `failed`, no status, sha256 `332fae09c005662d` | `failed`, no status, sha256 `dfa1aac893010e7d` |

Identical postures on different figures before; distinct honest abstentions after. §4.3 proven.
The baseline row was taken by restoring the committed file with `git show 04d4691:…` and
re-running, then restoring the fixed file — so the "before" is the real previous behaviour and
not a reconstruction.

The abstention is the wording already used by the categories holding no recorded answer:
*"no recorded answer is held for category A1 on these figures (prompt sha256 …), and there is no
model key in this environment to ask. Nothing is invented in its place."*

### Urgency: this affected a KEYLESS deployment only

`spec_apply.build_applier` returns the configured provider's applier the moment
`cfg.key_present()` and **never reads the recorded corpus at all**. Verified in the source. A
keyed deployment was never exposed to this.

### A consequence the owner must know

**The briefing's premise that the recorded file is keyed by a prompt sha256 is false.**
`research_fixtures/run76_recorded_a1_answer.json` has four keys: three `_`-prefixed notes and the
bare string **`"A1"`**. There is no hash in it. So with the fallback gone the recorded answer is
now **never served**, and the keyless environment has zero assessed categories rather than one
wrongly-assessed one.

That is the honest output §4.2 asks for, and I did not touch the fixture — it is sealed evidence
and §7.5/§8.6 put it out of scope. **To restore reproducibility the owner re-keys that one entry**:
replace the key `"A1"` with the sha256 of the exact prompt text generated for the figures the
answer was authored against (BAC 18,441,300, EV 2,217,200, AC 2,186,400 — the fixture's own
`_tcpi_arithmetic` and `_vac_arithmetic` state them). The applier prints the sha256 it wanted in
every abstention, so the value can be read straight off a run.

Iterations: **one**. Goal met.

## Premises in this order and briefing that proved false

1. **"The required core is A1, A2, A3, A6" (four).** The briefing said four. The tree says
   **five**: `("A1","A2","A3","A4","A6")`. The order's own §8.4 said "the required core of five"
   and was right; the briefing was wrong. This matters — it is one more required category that
   must carry a posture.
2. **"The recorded file is keyed by that prompt sha256 and the fallback simply bypasses it."**
   False. It is keyed by the bare string `"A1"`. There is no hash in the file, which is why the
   fix could not be the small re-pointing the briefing expected and why A1 now abstains.
3. **The briefing's hypothesis that the conflicting field would be "a percent, a count, a rate,
   a date" each individually correct.** The right shape, the wrong field class: it is a
   per-document *self-assessment*, which is a stronger result than "both are correct" — the two
   values are not comparable at all.
4. **Hypothesis two — "the conflict may not be scoped to the module that abstains" — is true, but
   it is deliberate, not a defect.** `documents.py:2029-2031` states it: *"The record describes
   the PERIOD'S EVIDENCE BASE, not one module's inputs, so it is written flat: `declared_evidence`
   applies a flat declaration to every module that asks."* Per-module scoping is not available
   without inventing per-module field lists, which the same comment block explicitly refuses
   (*"`required_inputs` is empty ON PURPOSE"*). **So I fixed the comparison, not the scope** —
   which is why the fix is one field rather than an architecture change.
5. **§2's framing that clearing the A6 gate is what stands between the platform and Green.**
   It was necessary and it is done, but it is not sufficient, and the reason is the bandless
   specifications. See the lead.
