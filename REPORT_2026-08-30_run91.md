### `assets/js/decision.js` — Run 69's change

Despite its name this file does not hold the participant's decision sequence. It holds the code
that decides what COLOUR four signal classes show. The change, in one sentence: **the platform
stopped inventing colour bands in the browser and started showing the band the server actually
computed.**

score — and applied its own red/amber/green thresholds to them. Those thresholds existed nowhere
else. On this platform's own fixture that produced a stored CPI of 0.952 showing **Green** in the

document class shows the band the document-risk module stored, and a class for which the server
stored no band shows nothing rather than a manufactured colour. The old threshold function is still
in the file, unreferenced, with a comment saying it must not be wired back in.

The portfolio list's colour changed the same way: a project the server has given no status now
reads "not yet analysed" instead of being coloured from whatever indices happened to be around.

**Does it change what a participant sees?** Yes — a colour on a signal class can differ, and can
now be absent where a colour used to be shown. **Does it change the order they see things in?** No.
**Does it change the options available to them?** No. No step, no gate, no lock, no randomisation,
no questionnaire, no control was added, moved or removed. The change makes the display agree with

## A5.5 — Rework Feedback Loop — RETIRED at Run 89, not in service

**Identity.** Live id `A5.5`. Method class `Rework_Feedback`. A genuine time-dependent stock and
flow model of work coming back.

**Required inputs.** `systemDynamicsModel` — a mapping, and the only input read. It must carry the
stock of work in the backlog, the work arriving and completed each step, and the share of completed

**Method.**
```
Backlog(t+1)       = Backlog(t) + NewWork(t) + ReworkGenerated(t) - WorkCompleted(t)

```

the number of steps run, the full per-step trace, the totals of new work, completed work and rework
generated, the rework share of completed work, and an **accounting residual** so a reader can check
the stock balanced.

**Bands.** **None. This module asserts no band and none may be attached.** Calibration-pending.

**Interpretation.** A backlog that rises while work is being completed is the signature of a
feedback loop: the project is generating work faster than it clears it, and the rework share says
how much of that is self-inflicted.

**Nothing to report.** The two sentences above, with `W` = *"a system dynamics rework model: the stock of
work in the backlog, the work arriving and completed each step, and the share of completed work

ExpectedValue(a) = sum over s of  cell(a, s) * P(s)
