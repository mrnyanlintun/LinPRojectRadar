# OG-SYNTH-0.6 — the Run-34 Portfolio Health calibration package

**Successor to `OG-SYNTH-0.5`, which is preserved byte for byte and is not rewritten.
`OG-SYNTH-0.1` to `0.4` behind it are likewise untouched.**

## Why this package exists

Run 34 addresses parameter provenance and calibration for PH.1–PH.5. The Run-33 package holds
*structural* fixtures — they establish that a method computes what its contract says. Calibration
needs something the structural fixtures deliberately do not carry: **labels**. This package adds
the two labelled datasets the predeclared Run-34 protocol names, and nothing else.

## What is in it

| file | role | contents |
|---|---|---|
| `run34_ph1_calibration_labelled.json` | CALIBRATION | 200 projects, 10 labelled anomalous, generator seed 340001 |
| `run34_ph1_holdout_labelled.json` | HOLDOUT | 200 projects, 10 labelled anomalous, **independent draw**, generator seed 340002 |

Both are generated by `server/tools/build_run34_calibration_fixtures.py` under one generative
specification: three standard-normal coordinates for a normal project, and a displacement onto a
shell at 5 standard deviations in a uniformly random direction for an anomalous one.

## Ground truth is defined before the detector, and before the data

The anomalous set is fixed by an **arithmetic property of the project identifier** — index
`i` is anomalous iff `i % 20 == 7` — decided before any feature value is drawn. The generative
mechanism is then applied *because* the project carries that label. **No detector is run in the
generator and no detector output settles any label.** The label causes the point; the point never
causes the label.

The holdout is not a different specification. It is the same specification re-run under a
different generator seed, which is exactly what makes it independent.

## What these fixtures establish, and what they do not

They establish numerical behaviour, stability, sensitivity, known anomaly separation, known
cohort effects and parameter trade-offs.

They establish **nothing** about real construction-project anomaly prevalence, field
false-positive rates, practitioner usefulness, operational business thresholds, or predictive
validity. Every file says so in its own fields:

```
data_origin = SYNTHETIC_RESEARCH_CALIBRATION
not_for_empirical_validation = true
ground_truth_defined_before_detector = true
```

**Synthetic calibration is not empirical field validation, and nothing in this package may be
reported as if it were.**
