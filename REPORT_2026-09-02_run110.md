# Run 110 — Nothing rigidly connected: what was measured, what was built, and what was not

**A MIGRATION WAS ADDED: `0032_raw_evidence_kind`. It widens the `observations.kind` CHECK
constraint from four values to five, admitting `RAW`, so that every value an extraction returns
can be stored as evidence. It adds no column, touches no existing row, and is required before
`projectupload` will accept a document on this code — `/readyz` reports 503 until
`alembic upgrade head` is run.**

No key was present and **no model call was simulated anywhere in this run.**

## THE HEADLINE, BEFORE ANYTHING ELSE

**The order's section 1 contains a stop condition, and it fired.**

> "If this measurement shows the change is larger or different from what section 0 describes,
> say so and stop."

It is different, in a way that decides the run. Section 0's mechanism is:

> "The model reads the stored evidence and applies the method… it can recognise that a value the
> document labelled one way is the quantity the specification asks for."

**There is no model key in this environment.** `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` and
`CLAUDE_API_KEY` are all absent — measured, not assumed. Extraction runs through
`extraction_client.StubExtractor`, which serves recorded extractions by sha256 and refuses
anything else. The specification layer runs through `spec_apply.RecordedSpecApplier`, which does
the same for prompts. **The recognition step at the centre of the ruling cannot be built end to
end and cannot be exercised.** Section 1.3 anticipated exactly this and said to "say so plainly
and adjust rather than simulating a model."

So I did not build it. Specifically, **I did not write a hand-coded synonym or alias table and
call it flexible matching.** A hand-written alias map is a new rigid connection wearing the word
"flexible" — it is the precise thing section 0 exists to remove, and presenting one as the ruling
implemented would have been the worst available outcome.

**What I built instead is the two pieces that are real, deterministic, and independent of a key:**
section 2.1 (every extracted value becomes evidence) and section 2.5 (the general guard). Both
are proved below on the real routes. **Sections 2.2, 2.3 and 2.4 are NOT built**, and the eight
blocked modules still do not produce readings. That is stated plainly rather than worked around.

### 1.1 — What the observations store holds, and where the real gate is

`oac_minutes` fields "produce no observation rows because they are not declared in

1. **`_NUMERIC_EMISSIONS[doc_type]` / `_DATESTR_EMISSIONS[doc_type]`** — a per-document-type map

## 3. WHAT WAS BUILT

### 3.1 — Section 2.1: every extracted value becomes evidence

`emit_observations` now emits, for **every key an extraction returns**, a row carrying the four
things the ruling names: **which document** (`document_id`, `sha256`, `doc_type`), **which period**
(applied at persistence), **what the document called it** (the label, verbatim) and **the value**
(untouched — not coerced, not rounded, not renamed).

The field name is `evidence:<doc_type>:<label>`. The colon is load-bearing: **no name in
`field_registry.ALL_SI_FIELDS` contains one**, asserted over the whole vocabulary in the suite, so
a RAW row cannot collide with or be mistaken for a declared field. `select_signal_inputs` iterates
`_KEY_ORDER` and cannot reach one.

Measured on the census fixture, after the change:

```
total observations : 247      RAW : 158      declared : 89

evidence:oac_minutes:weather_days_approved   = 7        | doc oac_minutes | period 1 | as_of 2026-03-31
evidence:oac_minutes:weather_days_claimed    = 9        | doc oac_minutes | period 1 | as_of 2026-03-31
evidence:oac_minutes:weather_allowance_days  = 10       | doc oac_minutes | period 1 | as_of 2026-03-31
evidence:oac_minutes:weather_approval_period = "2026-03"| doc oac_minutes | period 1 | as_of 2026-03-31
evidence:subcontractor_report:subcontractor_ratings_json = [{"Subcontractor": "Northline …
```

**Traceability (section 3.3) is strengthened, not weakened.** A RAW row records the document, the
period, the label and the value, which is more than the platform held before.

**It changes no reading, and that is asserted rather than asserted-about.** The suite hashes
`select_signal_inputs` over all rows and over the declared rows alone and requires the digests to
be equal. The census delta of zero is the same fact measured end to end.

**One consequence I had to handle, and it is the subtle part.** `_evidence_qualification` in
`documents.py` raises a *material conflict* when two documents of equal writer precedence, dated
the same, state different values for one field. Left alone, two documents each printing a column
called `report_period` with different values would have become a documentary contradiction, and
Category 9 would have gone to REVIEW_REQUIRED and blocked every gated module. **RAW rows are
therefore excluded from that comparison**, on the same principle the code already applies to
`docRiskScore`: the rule's force comes from the premise that the field names *one fact about the
project* which two documents assert incompatibly, and two coincident column headings have not
been shown to be two answers to one question. **Establishing that they are is the model-driven
step**, and it is not built. The suite proves the exclusion is not a suppression: the identical
disagreement between *declared* fields still raises a conflict.

### 3.2 — Section 2.5: the general guard, and it is the substantial one

`registry.run_all` wrapped both of its `run_module` call sites in a containment boundary. A module
that raises is recorded as a **failed reading** carrying `module_failed`, the exception type and
message, and the new stable code `module_execution_failed` — distinct from every evidence-absence
code, so a defect can never be mistaken for missing data on the ledger or in the analysis.
**Nothing is substituted** for the missing reading: no default, no band, no last-known value. The
full traceback is logged at ERROR. `BaseException` is deliberately not caught.

Offered as a recommendation, not a decision.
