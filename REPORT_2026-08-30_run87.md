## 3. The document contracts, verbatim, for the owner's generating model

### 3.1 Quality — `inspection_report` and `quality_audit_report`

Three new fields. Both types get the same three, because both print the same kind of population.

**`quality_requirements_json`** — a JSON array, one object per **printed row** of the requirement,
inspection-item, checklist or audit-findings table, using the table's own column headings as keys
and its values **as printed**. The document must print a table of this shape:

| Item ID | Requirement Description | Applicable | Assessed | Result | Criticality | Source | Corrective Action | Status |
|---|---|---|---|---|---|---|---|---|
| Q-001 | Concrete compressive strength at 28 days | Yes | Yes | Pass | High | Spec 03 30 00 | | |
| Q-003 | Structural weld visual inspection | Yes | Yes | Fail | Critical | AWS D1.1 | Re-weld joints W-14 to W-19 | Open |
| Q-009 | Elevator seismic restraint | Yes | No | Not inspected | High | ASME A17.1 | | |
| Q-010 | Marine works turbidity screen | No | No | | Low | Spec 35 00 00 | | |

**The three columns that decide the arithmetic, and the words that are recognised.**
*Applicable* / *Assessed* / *Result*. Affirmative words: `Yes, Y, True, Satisfied, Satisfactory,
Compliant, Conforming, Conforms, Pass, Passed, Accept, Accepted, Acceptable, Closed, Closed out,
Complete, Completed, Met, OK, Resolved, Cleared, No exception, No findings`. Negative words:
`No, N, False, Unsatisfied, Unsatisfactory, Non-compliant, Not compliant, Non-conforming,
Nonconformance, Fail, Failed, Reject, Rejected, Open, Outstanding, Unmet, Not met, Incomplete,
Unresolved, Overdue, Deficient, Deficiency, Violation, Exception, Breach`. Not-assessed words:
`Not assessed, Not inspected, Not verified, Not checked, Not reviewed, Not tested, Pending, TBD,
Scheduled, Deferred, N/A, Awaiting, Future`. **Any other word leaves the cell unset**, which puts
the row in the outstanding list — it never becomes satisfied.
*Criticality* — `Critical` or `High` are the two that make an unsatisfied row a **critical
exception**, carried separately and noncompensatorily. Other values are recorded and do not.

**`quality_register_id`** — the report's or register's own identifier exactly as printed
(e.g. `IR-2026-014`). **`quality_register_period`** — the period it covers as the document states it
(e.g. `2026-07`). Null for either the document does not state.

**Heading synonyms accepted for each column** (case and punctuation ignored): identity —
`Requirement ID / Requirement No / Requirement / Condition ID / Permit Condition / Observation ID /
Item ID / Item / Inspection Item / Checklist Item / Clause / Spec Section / ID / No / Ref`;
applicability — `Applicable / Applicability / Applies / In Scope / Relevant`; assessment —
`Assessed / Inspected / Verified / Checked / Reviewed / Tested / Witnessed / Evaluated`; outcome —
`Satisfied / Result / Outcome / Conformance / Conformity / Compliant / Compliance / Conforms /
Pass-Fail / Verdict / Disposition / Finding / Closure / Closure Status / Status`; criticality —
`Criticality / Critical / Severity / Priority / Risk Level / Classification / Grade / Category`.

**What is NOT asked for, and why.** `provenance` in the governed sense. The specification names it
on the row shape, but `canonical_v6.quality_compliance` reads it only to echo onto a critical
exception, never to compute; and a provenance sentence is not a thing a document prints in a
column. Per §2.1 it is left out and nothing is invented in its place. **No measurement is lost.**

**Where the document states less than a readable table, nothing is assembled and A6.1 goes on
abstaining honestly** — the corpus `recorded_audit_evidence` / `NOT_ESTIMABLE` path is untouched
and still stands behind it.

### 3.2 Environmental — `environmental_report`

Six new fields. **The document must state these on its face, in words. None may be inferred.**

| Field | What the document must state |
|---|---|
| `environmental_jurisdiction` | The jurisdiction the site sits in, e.g. `State of Alaska, Fairbanks North Star Borough` |
| `permitting_authority` | The authority that **issued** the permit, as named. Return the bare word `EPA` **only** where the document names the U.S. Environmental Protection Agency as the issuing authority; otherwise the state, tribal, local or other authority as printed |
| `permit_id` | The permit number, e.g. `AKR10ABCD` |
| `permit_version` | Its version or revision, e.g. `CGP 2022` |
| `permit_site_id` | The site identifier, e.g. `SITE-FBX-01` |
| `operator_status` | The operator's status under the permit, e.g. `Primary operator` |

**`environmental_requirements_json`** — a JSON array, one object per printed row of the
permit-condition, observation or corrective-action table:

| Permit Condition | Condition Description | Applicable | Closure Status | Severity | Corrective Action |
|---|---|---|---|---|---|
| C-1 | SWPPP inspections weekly | Yes | Closed | High | |
| C-4 | Concrete washout containment | Yes | Open | High | Install lined washout by 2026-08-15 |
| C-6 | Post-construction BMP certification | Yes | Pending | Medium | |

**The closure semantics** are exactly the vocabulary in §3.1: `Closed` is a satisfied condition,
`Open` is an unsatisfied one, `Pending` is outstanding and enters neither side of the ratio. An
open condition of severity `Critical` or `High` is returned as a **critical violation**, separately.

**The rule the platform applies to `permitting_authority`, so the generating model knows the stakes:**
only the exact value `EPA` sets the governing rule to the EPA Construction General Permit 2022;
anything else carries `rule: null` and the specification's own note. **Do not infer the authority
from the project's location, from the kind of work, or from general knowledge of who usually permits
such work.** Return null where the document does not state it — a jurisdiction with no authority
assembles nothing and the module correctly goes on reaching `APPLICABILITY_NOT_ESTABLISHED`.
